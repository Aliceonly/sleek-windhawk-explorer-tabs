> 历史设计记录（2026-10-26）。本页说明当时的方案，不代表当前功能已经完成。
> 最新实现状态见 [implementation-status.md](implementation-status.md)；设置 key 以 [配置设计](configuration-design.md) 为准。

所有已约定、且有可靠实现路径的用户行为，都设计为 Windhawk 配置。默认仍是 **Ctrl+Q 复制标签、Ctrl+中键后台打开、多文件夹 Enter 打开到一个新窗口**。性能与正确性修复不提供“恢复旧 bug”的开关。

## A 配置原则与优先级

界面按功能分组。基础项决定日常行为，高级项用于超时、节流和诊断。不为同一规则增加互相矛盾的开关。

本页是配置设计的最新版本。此前报告中的固定行为，除安全与正确性约束外，都视为这里的默认值。[七项功能方案](seven-feature-design.md) · [前五项实现研究](five-feature-design.md)

| 冲突场景 | 生效规则 |
|---|---|
| 功能关闭或当前版本不支持 | 不执行该功能，不尝试猜测私有接口 |
| Ctrl+Q 复制标签 | 使用复制标签组的配置，不套用 Ctrl+中键规则 |
| 批量打开 | 使用批量组的配置，不逐个执行“新标签自动切换” |
| Ctrl+中键 | 先用 Ctrl+中键配置，再考虑普通中键设置 |
| 来源设置为“跟随全局” | 使用原有 `selectNewTabs` |
| 用户随后主动切换 | 取消旧的待选任务，配置不能让它迟到抢焦点 |

表中的 key 是拟议内部标识；界面显示中文名称。所有选项目前都是设计，不代表功能已经实现或通过实机验证。

## B 标题、普通开标签与 Ctrl+中键

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `fixTabTitles` | 开 / 关 | 开 | 保留现有标题修复，不改虚拟目录的正常标题 |
| `selectNewTabs` | 开 / 关 | 开 | 保留现有全局自动切换设置 |
| `openTabs.folderMiddleClickFocus` | 跟随全局 / 前台 / 后台 / 系统默认 | 跟随全局 | 文件列表中的普通中键 |
| `openTabs.contextMenuFocus` | 跟随全局 / 前台 / 后台 / 系统默认 | 跟随全局 | 右键“在新标签页中打开” |
| `openTabs.position` | 系统默认 / 当前右侧 / 最右端 | 系统默认 | 普通开标签与地址栏默认位置 |
| `openTabs.ctrlMiddleClick` | 后台 / 前台 / 跟随普通中键 | 后台 | 只影响 Ctrl+中键，不影响 Ctrl+Q |

“后台”表示不主动切换；“系统默认”表示不覆盖该来源原生选择行为。关闭全局自动切换，不会禁用复制或批量打开，也不会覆盖它们各自的选择设置。

“+”和 Ctrl+T 保持系统行为，不被普通中键配置接管。Ctrl 必须在点击时捕获，不在延迟回调时重新读取。

## C 地址栏与文件拖放

**地址栏中键**

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `breadcrumb.enabled` | 开 / 关 | 开 | 地址栏面包屑中键功能总开关 |
| `breadcrumb.includeDropdown` | 开 / 关 | 开 | 是否处理面包屑下拉菜单中的目录 |
| `breadcrumb.focus` | 跟随全局 / 前台 / 后台 | 跟随全局 | 普通中键；Ctrl+中键仍有更高优先级 |
| `breadcrumb.position` | 跟随普通开标签 / 当前右侧 / 最右端 | 跟随普通开标签 | 允许独立设置地址栏的新标签位置 |

下拉菜单和特殊目录必须先解析出真实目标。开启配置不会绕过解析失败，也不会启用模拟键盘作为无声降级。

**拖文件到标签标题**

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `tabDrop.enabled` | 开 / 关 | 开 | 是否接管标题区域的文件投递 |
| `tabDrop.operation` | 移动 / 复制 / 系统规则 | 移动 | 系统规则遵循 Shell 的修饰键与跨盘规则 |
| `tabDrop.hoverDelayMs` | 0–1000 ms | 0 | 悬停多久后请求激活目标 tab；0 为立即 |
| `tabDrop.afterDrop` | 留在目标 tab / 返回拖入前的活动 tab | 留在目标 tab | 只在没有后续手动切换时执行返回 |
| `tabDrop.allowExternalSources` | 开 / 关 | 开 | 是否接收其他窗口或应用拖入的数据 |

固定移动或复制模式只接受对应的 Shell effect。源或目标不支持时拒绝，不能把复制结果谎报为移动。`afterDrop` 不等待网络文件传输结束后突然切回，而是在投递完成且操作意图仍有效时处理。

当前设计需要先激活目标，才能可靠确认目录。因此不提供未经验证的“完全不激活后台 tab 也能投递”选项。悬停延迟通过事件调度实现，不阻塞输入；未确认目标前显示禁止投递。

## D 关闭标签后的选择

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `closeTabs.selection` | 系统默认 / 最左 / 左邻 | 左邻 | 核心选择策略；系统默认等同不接管 |
| `closeTabs.scope` | 任意关闭 / 仅关闭活动 tab | 任意关闭 | 控制关闭后台 tab 时是否也切换 |
| `closeTabs.noLeftNeighbor` | 最左存活 tab / 系统默认 | 最左存活 tab | 仅“左邻”模式且没有左邻时生效 |

左右关系使用关闭前的真实显示顺序。关闭最后一个 tab 仍保持系统行为；本次不增加“阻止关窗或自动补建 tab”的新功能。标签迁移和整窗退出，不作为普通关闭处理。

## E 复制当前标签

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `duplicate.enabled` | 开 / 关 | 开 | 复制功能总开关 |
| `duplicate.shortcut` | 合法快捷键字符串；空值禁用快捷键 | `Ctrl+Q` | 只在 Explorer 内生效 |
| `duplicate.target` | 当前窗口 / 新窗口 | 当前窗口 | 新窗口模式复用已验证的窗口创建模块 |
| `duplicate.position` | 当前右侧 / 最右端 | 当前右侧 | 仅目标为当前窗口时生效 |
| `duplicate.focus` | 前台 / 后台 / 跟随全局 | 前台 | 后台新窗口模式需验证不抢焦点能力 |
| `duplicate.restoreSelection` | 开 / 关 | 开 | 恢复仍存在的所选项目，不复制文件 |
| `duplicate.scope` | Explorer 非编辑区域 / 仅文件列表 | Explorer 非编辑区域 | 重命名和文本输入始终排除 |

默认不注册 `Ctrl+D`。只有用户主动把快捷键改为它，才会覆盖它的原生含义；此类已知系统组合需明确提示冲突。快捷键配置用字符串输入和校验，不假定 Windhawk 自带按键录制控件。

复制始终创建新副本，不复用同目录 tab。完整导航历史和无法可靠恢复的搜索状态，不作为可勾选的虚假能力。

## F 多文件夹批量打开

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `batchOpen.enabled` | 开 / 关 | 开 | 批量打开总开关 |
| `batchOpen.shortcut` | 合法快捷键字符串；空值禁用 | `Enter` | 可改为 Ctrl+Enter；编辑场景始终排除 |
| `batchOpen.minimumFolders` | 1–1000 | 2 | 设为 1 才会改变单选目录行为 |
| `batchOpen.target` | 一个新窗口 / 当前窗口 | 一个新窗口 | 新窗口身份不明时停止，不能猜目标 |
| `batchOpen.order` | 当前视图 / 名称升序 / 名称降序 | 当前视图 | 名称排序使用 Shell 比较，同名保留视图次序 |
| `batchOpen.position` | 当前 tab 右侧 / 最右端 | 最右端 | 仅目标为当前窗口；整批保持连续次序 |
| `batchOpen.windowFocus` | 前台 / 后台 | 前台 | 不影响原窗口内容；后台创建能力需验证 |
| `batchOpen.selectedTab` | 本批第一项 / 本批最后一项 / 保留原活动项 | 本批第一项 | 新窗口没有原活动项时，回退本批第一项 |
| `batchOpen.mixedSelection` | 保留系统行为 / 只处理文件夹 | 保留系统行为 | 后者明确忽略混选文件，不打开它们 |
| `batchOpen.includeFolderShortcuts` | 开 / 关 | 关 | 开启后只处理能明确解析为目录的快捷方式 |
| `batchOpen.includeShellFolders` | 开 / 关 | 关 | 仅接受适配层验证过的可导航 Shell 文件夹 |
| `batchOpen.onError` | 继续剩余项 / 停止剩余项 | 继续剩余项 | 已经打开的 tab 不删除、不重新创建 |
| `batchOpen.maxFolders` | 0 或正整数 | 0 | 0 不限；超限时整批拒绝，不静默截断 |
| `batchOpen.cancelShortcut` | 合法快捷键字符串；空值禁用 | `Escape` | 仅在本批仍有排队项且目标窗口有焦点时生效 |

图标、详细列表和分组视图均按同一个顺序契约处理。“用户逐个点选的时间顺序”不提供为选项，因为当前设计没有追踪这段历史。

当前窗口模式中，“保留原活动项”会让整批标签后台创建。后台新窗口也可以预选本批第一项，但不主动激活该窗口；这两个设置不冲突。

`maxFolders` 不是性能保护必选项，默认不限制数量。取消只停止尚未提交的创建；不能用 Escape 关闭已开标签，也不应拦截其他窗口、菜单或编辑器的取消动作。

## G 高级：延迟、超时与日志

| 配置 key | 可选值 | 默认 | 说明 |
|---|---|---|---|
| `advanced.extraSelectDelayMs` | 0–1000 ms | 0 | 自愿增加的选择等待，不是必要等待 |
| `advanced.selectionDeadlineMs` | 100–10000 ms | 2000 | 到期取消旧焦点请求，不取消目录导航 |
| `advanced.batchCreateIntervalMs` | 0–1000 ms | 0 | 0 表示按就绪事件连续创建并让出消息循环 |
| `advanced.windowBindTimeoutMs` | 500–30000 ms | 5000 | 到期停止追加，不再猜测目标窗口 |
| `diagnostics.level` | 关闭 / 错误 / 调试 | 错误 | 调试级别用于定位事件与窗口关联 |
| `diagnostics.measureLatency` | 开 / 关 | 关 | 记录输入、创建、就绪、选择和投递耗时 |

上述数值是设计默认值，不是测量结果。额外选择延迟必须小于选择期限；设置冲突时不应用无效组合。任何非零延迟都使用消息或可取消计时器，不在输入回调中 Sleep。

路径和文件名不默认写入诊断日志。去重、跨线程保护、取消过期回调和正确释放对象是固定逻辑，不受日志或性能设置影响。

## H Windhawk 展示、校验与生效方式

使用标准 `WindhawkModSettings`：开关对应布尔值，策略对应字符串下拉框，快捷键对应文本，时间对应整数。设置按对象分组；不可用条件写入说明，不依赖界面自动隐藏。[Windhawk 官方设置与回调文档](https://github.com/ramensoftware/windhawk/wiki/Creating-a-new-mod)

```yaml title="设置声明示例 · 仅演示格式，尚未写入 cpp"
- duplicate:
    - enabled: true
      $name: 启用复制当前标签
    - shortcut: Ctrl+Q
      $name: 复制标签快捷键
    - focus: foreground
      $name: 打开后切换
      $options:
        - foreground: 切到副本
        - background: 留在原标签
        - inherit: 跟随全局
  $name: 复制当前标签
```

`Wh_GetIntSetting` 读取布尔与整数，`Wh_GetStringSetting` 读取字符串；读取后的字符串按文档释放。`Wh_ModSettingsChanged` 装载新的配置快照，必要时请求 mod 重载。普通行为变更优先热更新，不要求重启 Explorer。

| 校验或更新场景 | 约定 |
|---|---|
| 两个已启用动作绑定同一快捷键 | 拒绝冲突组合，保留上次有效配置并报告原因 |
| 未知枚举、非法快捷键、越界数值 | 不按猜测执行；保留有效配置并报告字段 |
| 关闭功能 | 新事件立即不再接管，取消尚未提交的任务 |
| 拖放中修改移动为复制 | 当前会话保持原配置，下一次拖放才生效 |
| 批量任务中修改排序或目标 | 当前批次保持原快照，新配置用于下一批 |
| Windows 版本缺少所需能力 | 不因配置开启而绕过探测，记录不支持原因 |
| 从旧版升级 | 保留 `fixTabTitles` 和 `selectNewTabs` 的用户值 |

迁移时要区分“新增字段尚不存在”和“用户明确设为 false 或 0”。七项功能尚未实施，之前报告里的拟议 key 可以统一改名；现有两个真实配置键不能随意改变语义。

以下约束始终生效。目标目录必须明确，文件操作必须受源和目标支持。编辑态不吞 Enter，跨线程不使用悬空对象。批量项不能静默丢弃，也不重新引入模拟键盘延迟链。

涉及后台新窗口、Shell 特殊目录与文件夹快捷方式的选项，先完成能力验证再开放。不要用一个看似可选、实际无效的配置冒充功能支持。本轮只更新配置设计，仓库代码保持不变。
